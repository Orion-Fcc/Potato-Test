## 一、本轮改了什么

按"你会有什么可感知变化"分组，不是按文件。

### 1. 回放不再拉伸，和你手动开 Edge 一模一样

- 录像规格改成 **1434 × 825**（`app/config.py` 的 `video_width/height`），**和视口 1:1**。回放时播放器不再上下/左右拉伸，画面比例和你手动测试时的窗口完全一致。
- 代价：每帧像素从约 102 万涨到约 118 万，编码 CPU 约 +16%；对被测对象零影响（视口才是布局依据，录像只是回放素材）。
- 关键约束：视口参数在 `executor.py` 的**两处 `Browser(`** 都接上了（`make_browser` 与 `capture_session`）。只接一处会导致"捕获登录态是一种布局、执行时是另一种布局"，症状偶发难查。
- 红线：视口只能因为"和手动环境对齐"而改，**不能为提速去动**——改视口等于改变被测对象本身。

### 2. 失败清单 + 助手改用例 + 改动留痕

给"项目里所有没通过的用例"生成一份**可执行清单**，而不是把人话理由堆给你。

- 新端点 `GET /api/projects/{pid}/failure-digest`，只取每条用例**最近一次未通过**结果。
- **合并靠确定性证据，不靠 LLM 语义聚类**（`app/failure_digest.py`）：相同根因、相同闸门、相同报错的用例归一组，不同根因绝不合并，未白名单的根因不合并。LLM 只负责"给历史没分类的结果补一个 `root_cause`"（`failure_backfill.py`），补完落库缓存，不会重复调。
- 前端 `FailureDigestPanel`：默认 `backfill=false`（首屏不拖慢），你点"补全分类"才触发 LLM 回填。
- 助手**可以改用例**：`PUT /api/testcases/{cid}` 带 `x-change-source: assistant` 请求头，改完自动写进审计表。
- 审计表 `case_change`（`app/models.py` 的 `CaseChange`）：字段级记录"改了什么字段、改前、改后、谁改的、来自哪条失败清单"。新端点 `GET /api/projects/{pid}/case-changes` 可查。

### 3. 治 agent 过早放弃 + 判定器编造结论

这是本轮最核心的一组改动，目标是让"跑出来的通过/失败"更可信。

- **agent 不再一遇障碍就放弃**：`executor.py` 新增 `_PERSIST_RULE`（核心语义：放弃是最后手段，不是第一反应）。允许"多花点时间"，但**禁止无效重复操作**（同一动作失败两次就停，靠 `_ANTI_WASTE_RULE` 约束）。
- **判定器会编造截图/数字证据**，在它之前加了两层确定性防线（`app/judge_claims.py`，纯规则、零 IO、不调 LLM）：
  - 结论里出现的数字（"查询后应有 N 条"）若在步骤记录里没有对应观察 → 判为"没测到"，不是缺陷；
  - 最后一步 `action=done` 但同一步 `result` 仍显示操作进行中 → 执行未落位，判 `agent_incomplete` 而非 `product_defect`；
  - 命中且判定器说"通过"时，`override_gate` 在出口**直接翻案为 failed**。
- 提示词拼接顺序被测试钉死：`_ADAPT_RULE` → `_PERSIST_RULE` → `_SELF_CHECK_RULE`（`_SELF_CHECK_RULE` 永远最后）。"只放宽怎么走到目标，绝不放宽什么算证据"。
- 还有一条老闸门 `judge_gate.py`：`agent_declined`（通篇无成功陈述 + 明确放弃）/ `page_not_ready`（最后一步仍卡加载占位且 0 可交互）命中时**不调 LLM**。

### 4. 导航后自动等页面就绪（代码层，不占步数）

- `executor.py` 新增 `_wait_until_ready`：批处理里若本批动作含 `navigate` / `go_back`，自动 CDP 轮询 DOM，直到出现可交互元素或超时，再进入下一步。
- 这一步**不消耗 agent 步数**——它不是让 agent 多走一步，而是执行器层面保证"页面真就绪了才往下走"。
- 回归修复：`_wait_until_ready` 里曾误用 `await _time.sleep(...)`（同步 sleep 不能 await），导致 18 条用例全 error、无有效结论。已改为 `await _aio.sleep(...)`（`import asyncio as _aio`），并有专门测试 `tests/test_wait_until_ready.py` 钉住（拆掉就变红）。

### 5. CI / 数据脱敏的附带修复

- 4 条 Windows/Line、干净环境下 pytest 假失败已修（`e8b7821`、`eb8a6fe`）；`mypy` 锁 1.x（`223e9ac`）。
- 测试数据里的真实内网地址已换成 RFC 2606 保留域名（`example.invalid` 等），推送前 `check_secrets.py --head` 把关。

## 五、已知限制与可回退项

- **429 网关限流**：LLM 额度耗尽时运行会中断，这是网关侧问题，代码层不解决。跑大批量前留意额度。
- **回填走 LLM 有合并风险**：失败清单的"合并"本身是确定性的（可复现、可审计），LLM 只补 `root_cause`；若某条分类明显不对，可清掉该条缓存重新回填。
- **视口/录像对齐是"和手动环境一致"**，不是"更快"。要改视口唯一合法理由仍是"和手动测试环境对齐"。
- 回退：本轮所有改动都在独立 commit（`06172cc`→`e8b7821`），`git revert` 或 `git reset` 到前一个 commit 即可整体回退，不影响更早的功能。
